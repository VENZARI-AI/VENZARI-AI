<summary><strong>How the modes work in practice</strong> — Click to expand</summary>

**Discover** before planning — AI reads everything, writes nothing, understands before changing. The Discover report documents what exists, what the constraints are, what the AI learned. No code changes permitted.

**Plan** before implementing — AI writes a document that can be reviewed before a line of code changes. The plan is structured: objective, approach, files affected, tests required, rollback strategy. A human reviews and approves the plan. Only then does Implement mode unlock.

**Implement** within scope only — AI writes code, but only within the scope defined in the approved plan. Structural constraints, not prompt instructions. The Tool Guard enforces allowlists at the system call level. AI cannot call `rm`, cannot access files outside scope, cannot modify `.git/` directly.

**Validate** with real evidence — AI runs tests and produces **actual test output**, not claims. "The tests pass" is not evidence. The test runner's stdout showing GREEN is evidence. The Evidence Collector logs the full output. It follows the commit.

**Review** before committing — AI enters read-only mode, performs static analysis, runs security scanners, produces a review report. The review includes: code quality signals, security findings, test coverage delta, complexity metrics. A human reviews the report.

**Commit** with evidence — the only mode where git operations are allowed. AI stages specific files, writes a structured commit message, attaches the full evidence chain (Discover report, Plan document, Validate output, Review report). The commit is traceable. Six months later, you know exactly what the AI did and why.

The loop detector monitors for repeated failures. Three identical attempts without progress → CODE stops, escalates to human review, logs the loop. No infinite burn.

### 3-Signal Memory

Three-signal memory retrieval — semantic + exact + importance:

| Signal | Method | Speed | What it finds |
|--------|--------|-------|---------------|
| **Vector embeddings** | Semantic search | ~50ms | *"What did we discuss about billing?"* — relevant content even without exact word match |
| **BM25 full-text** | Exact phrase search | ~10ms | Code snippets, precise phrases, error messages, IDs |
| **PageRank graph** | Importance ranking | ~5ms | Most-referenced facts, key decisions, high-impact memories |

**Nothing falls through.** If it's relevant semantically, the vector index finds it. If it's an exact phrase, BM25 finds it. If it's been referenced many times, PageRank elevates it.

<details>
<summary><strong>Why three signals, not one</strong> — Click to expand</summary>

<br/>

**Vector-only systems miss exact matches.** You say *"What's the database password?"* The agent returns semantically similar content about passwords in general, but misses the specific environment variable name `DB_PASSWORD=xkcd_CorrectHorseBatteryStaple`.

**Keyword-only systems miss meaning.** You say *"How do we handle refunds?"* The agent searches for the word "refund" and finds nothing, because your team calls them "credit reversals" internally.

**Unranked systems bury important facts.** You say *"What's our GDPR policy?"* The agent returns 50 matches, sorted by recency. The actual policy document from 8 months ago is match #47.

**Three signals cover all three problems.** Vector for meaning. BM25 for precision. PageRank for importance. The agent fuses all three and returns the best match.

</details>

### The Nightly Learning Loop

Every night at 3am (configurable), the agent:

1. **Analyzes patterns** — which requests are repeated, which skills are underperforming, which responses get corrections
2. **Creates new skills** — if you ask the same multi-step workflow 5 times, the agent creates a single skill for it
3. **Improves existing skills** — if a skill fails or produces poor results, the agent generates an improved version
4. **Compresses memory** — old conversations are summarized, embeddings are rebuilt, graph is updated
5. **Updates context model** — learns which facts are important, which relationships matter, which queries predict which needs

### 8-Provider Model Router

The agent routes inference across 8 providers automatically:

`Local inference` → `Groq` → `Gemini` → `OpenRouter` → `Cerebras` → `Anthropic` → `OpenAI` → `Bedrock`

**Circuit breaker:** 3 failures from a provider → bypass it, try next provider, auto-recovery probe after cooldown

**Budget monitor:** approaching session budget limit → downgrade to cheaper model tier, alert user

**ENGINE integration:** if VENZARI ENGINE is installed, all calls route through ENGINE's local AI gateway with zero configuration

**Different providers for different needs:**

- **Local inference** for privacy and zero cost (if you have GPU capacity)

- **Cerebras** for ultra-fast inference (1,800 tokens/sec on Llama-3.3-70B)
- **Anthropic** for Claude Opus/Sonnet/Haiku (highest quality reasoning)
- **OpenAI** for GPT-4o (best for structured output and function calling)
- **Bedrock** for enterprise compliance (AWS-hosted models)

**You configure all 8 once. The agent picks the right one for each task automatically.**
