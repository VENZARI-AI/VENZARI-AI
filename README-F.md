### The 3-Stage Installer — Why It Matters

<details>
<summary><strong>Stage 1: 11 parallel pre-install checks — Before any wizard question</strong></summary>

<br/>

RAM (fail <8GB) · Disk (fail <60GB) · CPU (warn <4 cores) · OS (Ubuntu 22.04/24.04 only) · Container runtime (installed + running) · Ports (80, 443, 3000, 5432, 6379 available) · Internet (required for install) · Sudo access · Existing install detection · GPU detection (optional) · Python 3.10+

Any failure stops with exact fix instructions. No partial states. No mystery errors halfway through.

</details>

<details>
<summary><strong>Stage 2: 7-question wizard — Configures what can't be auto-detected</strong></summary>

<br/>

1. Server identity (domain or IP)
2. License key (validates tier + seats)
3. AI provider preference (local-only | local+cloud | cloud-only)
4. Model selection (hardware-adaptive recommendations)
5. SSL mode (auto Let's Encrypt | manual cert | HTTP only)
6. Telemetry (anonymous install success ping yes/no)
7. Optional add-ons (voice, custom training, workflow automation)

That's it. Seven questions. Everything else is auto-detected.

</details>

<details>
<summary><strong>Stage 3: 17-step hardware-customized plan — From the VENZARI installer service</strong></summary>

<br/>

Your hardware profile + license sent to the VENZARI installer service. Returns 17-step plan customized for your CPU, RAM, GPU, disk, license tier.

Binary (verified download) → models → service startup → health checks → SSL → ecosystem wiring → MCP registration → tier features

**Resumable:** Step 9 fails? Run the resume-repair command. It skips steps 1–8 (complete) and retries from 9.

**2,301 tests** cover every step, every retry, every hardware config from 8GB RAM / 2-core to 256GB RAM / 64-core + A100.

</details>

### The Companion System — `.venzari/` in Your Project

```
.venzari/
  ├── agents/          Configured roles with specific capabilities
  ├── skills/          24 native + 216 vendor task templates
  ├── tasks/           Structured definitions with opening/closing gates
  ├── rules/           Project-specific constraints (overrides defaults)
  ├── memory/          Session history, codegraph, architectural decisions
  └── gates/           Automated checks before task completion
```

**What this means:** Return months later. CODE reads the companion and knows where you left off. When you correct the AI, that correction becomes a rule. The system gets better at your project over time.

### Five Governance Components

| Component | Enforcement |
|-----------|------------|
| **SSOT Loader** | Project rules loaded before every action |
| **Tool Guard** | Per-mode allowlists at system call level — structural, not prompt-based |
| **Loop Detector** | 3 identical attempts without progress → stop, escalate |
| **Evidence Collector** | Every tool call logged: input, output, timestamp. Immutable. Follows commit. |
| **Context Assembler** | Synthetic context under 4,000 chars — most relevant knowledge, no overflow |
